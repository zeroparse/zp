# Public Go Packages

This chapter defines the Go packages that ZeroParse exports: which packages exist, what each is for, and the
exported API of the packages that no other chapter defines (`gen`, `grammar`, `testing/sample` and
`testing/editfuzz`). The contract of the other packages is defined where their subject is: `zp` in
[Parsing](parsing.md), [Nodes and Values](nodes.md), [Incremental Documents](documents.md) and
[Streaming](streaming.md); `schema` and `query` in [Output Schemas and Structural Queries](schemas-and-queries.md);
`lint` in [Grammar Lint](lint.md).

## Scope and Terminology

The **public packages** are the packages under the module path `zeroparse.dev/zp` that are not below an `internal`
directory. Only their exported names are part of the contract; a name that is not exported, and every package
below `internal`, may change without notice. A **configuration** is a value of an exported struct type whose fields
select the behavior of an operation, such as `gen.Go`.

### The `gen` Package

Package `gen` generates the source of a parser from a grammar. A **generator** holds the settings of one generation
in a configuration value; `gen.Go` generates a Go package and `gen.TypeScript` a TypeScript module. Both implement
the interface `gen.Generator`, which the command `zp gen` uses.

```go
type Generator interface {
    Generate(g *grammar.Grammar, start string) ([]File, error)
    GenerateRuntime() ([]File, error)
}
type File = ... // a file of generated code: its slash-separated Path, relative to the directory of the package, and its content
```

- `Generate` generates the files of a parser whose entry points parse from the rule `start`, which MUST be a start
  rule of `g`; an empty `start` selects the default start rule. It returns an error, and no files, if `g` does not
  compile, `start` is not a start rule, or the configuration is invalid. The same grammar, start rule and
  configuration give the same files.
- `GenerateRuntime` generates only the runtime, which does not depend on a grammar, to refresh the copy that a
  parser generated with `RuntimeEmbed` carries without regenerating the parser. `gen.Go` uses only its `Module`
  (for the package path of the copy) and `gen.TypeScript` none of its settings.

`gen.RuntimeMode` selects how generated code reaches its runtime:

| Value | Name | Meaning |
|:--|:--|:--|
| `RuntimeEmbed` (the zero value) | `embed` | A copy of the runtime is written next to the parser (the package `internal/runtime` in Go, `runtime.ts` in TypeScript), so the generated code depends on nothing else |
| `RuntimeImport` | `import` | The parser imports the runtime: `zeroparse.dev/zp/runtime` in Go, the module `TypeScript.RuntimeModule` in TypeScript |

`RuntimeMode.String` returns `embed` or `import`, and `RuntimeMode(n)` for a value that names no mode.

#### gen.Go

`gen.Go` configures a Go parser. Its zero value generates an untyped parser with an embedded runtime; `Module` MUST
be set unless `Runtime` is `RuntimeImport`, `PackageName` is set and `Types` is false. `Go.Generate` returns
`parser.go`, the code generated from the grammar; `api.go`, which re-exports the runtime names that users of the
parser need; with `Types`, `types/types.go`, the package `Module/types` that declares the Go types of the grammar;
and with `RuntimeEmbed`, the files of the runtime copy under `internal/runtime`.

| Field | Meaning |
|:--|:--|
| `Module` | The import path of the generated package |
| `PackageName` | The package name; defaults to the last element of `Module` without a major version suffix |
| `Runtime` | A `RuntimeMode`; `RuntimeEmbed` by default |
| `Types` | Generate declarations for the grammar's types and the typed entry points `ParseAST` and `ParseRuleAST`; needs `Module` |
| `DefaultValue` | Produce default values, as the option `WithDefaultValue` of `zp` does; cannot be combined with `Types` |
| `SourceInfo`, `Expectations` | Record source information and syntax error expectations, as the options `WithSourceInfo` and `WithExpectations` of `zp` do. Without `Expectations`, a syntax error has an empty expected list and no messages |
| `Observability` | Emit rule tracing and profiling, including for typed entry points |
| `LimitControls` | Generate the limit-controlled form, which supports cancellation and the compute limit; without it, a parse that passes a context or a finite compute limit returns an error. The input and depth limits work in both forms |
| `Recognize` | Also generate `Recognize`, which checks the input without building a tree |
| `MaxDepth` | The default nested rule-call limit; zero selects 100,000 and a negative value is an error |
| `Document`, `Stream` | Generate a mutable incremental `Document`, and `ParseStream` (and with `Types`, `ParseStreamAST` and `IterateAST`); `Stream` needs a `#stream` repetition in the start rule |
| `TypedOnly` | Generate only the typed entry points; needs `Types` and cannot be combined with `Recognize`, `Document` or `Stream` |
| `OmitPackageDoc` | Leave out the package comment |
| `Optimize`, `Opt`, `NoOpt` | The optimization profile (`speed`, the default, `memory` or `size`), per-optimization values, and optimizations to turn off (which wins over `Opt`). No optimization changes what a parser returns; an unknown name or an unsupported value is an error |
| `PrintAfter`, `PrintTo` | Write the intermediate representation after the named passes (`build`, a pass name or `all`) to `PrintTo`, which `PrintAfter` requires |

The fields correspond to the flags of `zp gen` in [Generated Parsers](generated-parsers.md#the-generator).

#### gen.TypeScript

`gen.TypeScript` configures a TypeScript parser, and its zero value generates an untyped parser with an embedded
runtime. `TypeScript.Generate` returns `runtime.ts` (with `RuntimeEmbed`), `parser.ts`, and with `Types`, `types.ts`.
Generated TypeScript parsers have no stream or incremental parsing. Its fields have the meaning of the fields of
`gen.Go` of the same name (`Runtime`, `Types`, `DefaultValue`, `SourceInfo`, `Expectations`, `Observability`,
`LimitControls`, `Recognize`, `MaxDepth`, `Optimize`, `Opt`, `NoOpt`, `PrintAfter`, `PrintTo`), with these differences:
the runtime is the module `RuntimeModule`, a module specifier such as `@scope/zp-runtime` or `../shared/runtime.ts`,
which `RuntimeImport` requires and every other mode rejects; the typed entry points are `parseAST` and
`parseASTWithOptions`, which convert the completed result into plain objects and arrays; cancellation is a signal
option; and `MaxDepth` must be an exact JavaScript integer.

### The `grammar` Package

Package `grammar` defines the abstract syntax tree (AST) of grammars and the operations on it that do not need a
compiler. The parser of ZeroParse source and the compiler are in `zp`, not in this package: a `*grammar.Grammar`
is obtained from source by `zp.ParseGrammar`, from a parser compiled from source by `Parser.Grammar`, or from JSON
by `UnmarshalJSON` and `DecodeJSON`.

#### The Tree

A `Grammar` holds one `File` (member `File`). A `File` has a package clause (`Pkg`, whose zero value means that
there is none) and an ordered list of declarations (`Decls`). The AST has one exported struct type for each
construct of the [Grammar Language](../language/README.md); each type's fields hold the construct's parts, and the
types fall into families that are Go interfaces:

| Family | Interface | Members |
|:--|:--|:--|
| Declarations | `Decl` (with `DeclName` and `Diagnostic`), and the refinements `TypeDecl`, `VarDecl` and `RuleDecl` | `TypeDef` and `TypeAlias` (types), `VarDef` (variables), `RuleDef` (rules) |
| Parser expressions | `Expr` | The expressions of [Parser Expressions](../language/parser-expressions.md) and the pragmas of [Pragmas](../language/pragmas.md): sequences, choices, repetitions, predicates, calls, literals, character classes, anchors, captures, discards, cuts, recovery, streams, Operators Rules and the like |
| Value expressions | `Term` | The expressions of actions and predicates ([Actions](../language/actions.md), [Predicates](../language/predicates.md)): literals, capture and variable references, members, operators, lambdas, constructors, casts |
| Type expressions | `TypeExpr` | The type forms of [Types](../language/types.md): references, applications, struct, tuple, list and optional types, joins and meets |

The interfaces are sealed: only the types of this package implement them. A node that carries source information
implements `SourceNode`, whose `Source` returns its `SourceInfo`. `SourceInfo` records the node's span (`Pos`,
inclusive, and `End`, exclusive, as 1-based positions in code points; zero when unknown), a position for
diagnostics when it differs from `Pos`, and its comments. A `Pos` has a 1-based `Line` and `Col`, and the zero
value means that the position is unknown (`IsValid` reports whether it is known).

`Grammar` has the methods `Rules`, `Types` and `Vars`, which return the declarations of each kind in order,
`AllComments`, `Clone`, which returns a deep copy, and context-aware forms `RulesContext`, `TypesContext` and
`AllCommentsContext`. A tree MAY share subtrees but MUST NOT contain a pointer cycle. A caller MUST NOT mutate a
tree while another operation of this package or a compile or generation runs on it.

#### Formatting

| Function | Result |
|:--|:--|
| `Format(g)` | The grammar as ZeroParse source. Comments and line breaks recorded in the tree are kept, so formatting parsed source preserves its comments and layout; a tree without layout (decoded from JSON, for example) is printed with a blank line between definitions and one item per line in blocks |
| `FormatSyntax(g)` | A documentation view of the parsing syntax: type declarations, result annotations, actions, captures, metadata attributes and recovery wrappers are omitted. It is not an equivalent parser, and `g` is not modified |
| `FormatExpr(e)`, `FormatTerm(t)`, `FormatType(t)` | One parser expression, value expression or type expression in ZeroParse syntax |
| `FormatContext`, `FormatExprContext`, `FormatTermContext`, `FormatTypeContext` | The same, with cooperative cancellation: a canceled context returns the empty string and the context's error, never partial source |

#### JSON

`MarshalJSON(g)` encodes a grammar as JSON. `UnmarshalJSON(data)` decodes one complete JSON value and checks it
with `Validate`; unknown members and duplicate keys keep the permissive behavior of `encoding/json`.
`DecodeJSON(data)` decodes one complete value, rejects unknown members and duplicate keys, and validates the result.
A strict intake error is a `*JSONDecodeError` with `Path`, the zero-based byte `Offset` of the offending token,
`Msg` and the `Cause`, which `Unwrap` returns. Layout and comment placement used only for formatting are not
serialized.

#### Validation

`Validate(g)` checks, without modifying `g`, that required children are present, positional references are not
negative, repetition and character-range bounds are consistent, and the tree has no pointer cycle. An optional
child MAY be nil, but an interface that holds a nil pointer is invalid. It returns the first problem, in
depth-first order and checking a node's bounds before its children, as a `*ValidationError` with the `Path`
(JSON member names and zero-based indexes), the closest known `Pos` and `Msg`, or nil. It imposes no size or depth
limit. Name resolution, types, attributes and Operators Rule semantics are checked by the compiler.
`ValidateContext` is `Validate` with cancellation.

#### Helpers

`RuleOperators(e)` returns the Operators Rule that `e` is, or that `e` holds when the pragma `#ignorecase` follows
its block, together with the pragma node that carries it, or nil for any other expression. `TypeRefs(node)` returns
the type references in the tree rooted at `node`, in tree order, a shared reference once.

### Package testing/sample

Package `sample` generates inputs that a grammar accepts, for testing code that consumes parse results and for
seeding fuzz tests. It needs a parser compiled from grammar source: a parser loaded from a compiled grammar has no
grammar AST and cannot be sampled. The command `zp sample` offers the same generation.

**Guarantees.** Every input that the generator returns has been parsed by the parser and accepted without errors,
also without errors recovered with `#recover`. The decisions are reproducible: the same parser, options and seed give
the same inputs with the same version of the package, on any Go release. The algorithm MAY change between versions.
Recursion and length are bounded softly, and the search is bounded hard.

| Function | Behavior |
|:--|:--|
| `Generate(p, n, opts...)` | Returns up to `n` distinct accepted inputs; see `Generator.Generate` |
| `New(p, opts...)` | Returns a `*Generator` that starts at the start rule of `p`. It is not safe for concurrent use |
| `Seed(f, p, n, opts...)` | Adds up to `n` distinct accepted inputs to the seed corpus of the fuzz test `f` (an `F`, the part of `*testing.F` that it uses: `Helper`, `Add` and `Fatalf`), each as one string argument, so the fuzz target takes one string. It checks each input again and fails `f` if it generates none |

| `Generator` method | Behavior |
|:--|:--|
| `Next()` | An accepted input (inputs MAY repeat), or `ErrNoInput` if no candidate was accepted within the attempts |
| `Generate(n)` | Up to `n` distinct accepted inputs; fewer when no more are found, and `ErrNoInput` if none |
| `Invalid()` | One near-miss invalid input: an accepted input changed by one mutation that the parser rejects. `ErrNoInput` if no valid input is found, `ErrNoInvalid` if no mutation is rejected (a grammar such as `.*` accepts everything) |
| `GenerateInvalid(n)` | Up to `n` near-miss inputs with distinct `Input`; the errors of `Invalid` if none |
| `Coverage()`, `Cuts()`, `Stats()` | Coverage of the accepted inputs, the cuts of each rule, and the counts of the work done |

An `Invalid` has the mutated `Input`, the valid `Base` it was made from, a description of the `Mutation` (byte
offsets in `Base`) and the `Err` that the parser returned for `Input`. `ErrNoInput` and `ErrNoInvalid` are
sentinel errors: the errors returned wrap them with what became of the attempts, so test them with `errors.Is`.

| Option | Meaning | Default |
|:--|:--|--:|
| `WithSeed(seed)` | The seed of the random decisions | 0 |
| `WithAttempts(n)` | Candidates tried for one input before giving up | `DefaultAttempts` = 100 |
| `WithBudget(steps)` | Steps one attempt may take (a generated expression or an inspected Operators Rule scope) before giving up; it also bounds the search stack | `DefaultBudget` = 20000 |
| `WithMaxDepth(d)` | Soft bound on recursion: past `d` nested calls of rules already active, the generator prefers the shortest way to finish; the search never goes deeper than `d + 8` | `DefaultMaxDepth` = 5 |
| `WithMaxRepeat(n)` | Iterations an unbounded repetition aims for beyond its minimum, at most; the search never takes more than `8 × n + 4` beyond the minimum | `DefaultMaxRepeat` = 3 |
| `WithMaxLen(n)` | Soft limit on the length of an input in bytes | `DefaultMaxLen` = 512 |
| `WithCoverage()` | Prefer rules and alternatives that no accepted input has exercised | off |

`Coverage` has the counts `Rules` and `RulesCovered`, `Alternatives` and `AlternativesCovered` (the alternatives of
ordered choices and the operands and operators of Operators Rules that can match), the lists `MissedRules` and
`MissedAlternatives` (each an `Alternative` with its `Rule`, `Kind` of `choice`, `operand` or `operator`, `Index`
and `Expr`), and the lists `Unreachable` (rules that generation cannot exercise from the start rule) and
`Impossible` (rules the start rule calls that can never match). It is measured on the way the generator derived each
input, so its counts are close to, but not guaranteed to equal, the parser's own coverage. `String` summarizes it on
one line and `Report` gives one item per line. `Stats` counts `Candidates`, `Rejected`, `Failed`, `Exhausted`
(failed searches that used up their budget), `Duplicates`, `CheckCuts` and `PredicateCuts`. `Cuts` returns a
`RuleCuts` (the `Rule`, `Checks` and `Predicates`) for each rule that has cuts, the most cuts first and ties in
rule name order.

### Package testing/editfuzz

Package `editfuzz` checks incremental parsing against fresh parses. It applies sequences of edits to a
`zp.Document` and, at the start and at each checkpoint, compares the document's parse result with a fresh parse of
the document's current text: the values with their spans, and the errors with their positions, expectations and
messages. A failing sequence is saved as a file that replays it exactly. The command `zp edit-fuzz` offers the
same operations, and the file format is defined in [Fixture Suites and Edit Sequences](test-formats.md).

A **sequence** (`Sequence`) is a versioned event log for one grammar, start rule, backend and position unit: the
hex SHA-256 hash of the exact grammar source bytes (`GrammarSHA256`), `Start`, `Backend`, `Unit`, the `Initial`
text, the `Operations`, the generating `Seed` (provenance only; replay does not use it) and the `Limits` of a replay
(not recorded in the saved format; a replay supplies them again). Text and replacements are exact bytes, including
invalid UTF-8, so replay does not depend on the random generator. An `Operation` has a `Kind` and, for an edit, a
`Start`, `End` (positions in the sequence's unit in the text immediately before the operation) and replacement `Text`:

| `Kind` | Operation |
|:--|:--|
| `Edit` | Replace `[Start, End)` with `Text` |
| `Undo` | Restore the text before the latest edit that is not undone |
| `Redo` | Reapply the latest undone edit; a new edit discards the edits that can be redone |
| `Checkpoint` | Parse the document and compare the result with a fresh parse |

| Function | Behavior |
|:--|:--|
| `Fuzz(src, opts)` | Runs generated sequences on documents of the grammar source `src`. Returns nil if every checkpoint matched, and a `*Failure` for the first sequence that did not, after saving it to `opts.SaveFailures` if set. Other errors report an unusable grammar, options or directory |
| `Replay(src, seq)` | Applies `seq` to a document of `src` and compares at the initial text and each checkpoint. Returns nil, a `*Mismatch` for the first difference, or an `*InvalidError` if the sequence cannot be applied |
| `Minimize(src, seq, maxAttempts)` | Shortens a sequence that fails with a `*Mismatch` while it fails with the same `Fingerprint`: it removes operations, then characters of the initial text, then bytes of replacements, and makes edits insertions or deletions. It replays at most `maxAttempts` candidates (`DefaultMaxAttempts` = 2000 if zero) and returns the shortest failing sequence and its mismatch; `seq` is not modified |
| `Save(dir, seq)` | Writes `seq` to a file named after a hash of its contents in `dir`, which appears complete or not at all, and returns its path. An existing file is never replaced: the same contents return the path, other contents an error |
| `Load(path)` | Reads a sequence saved by `Save` |
| `GrammarHash(src)` | The hash a sequence records for `src` |
| `ParseBackend(name)`, `ParseUnit(name)` | The backend named `closure`, `bytecode` or `bytecode-iterative`, and the unit named `codepoints` or `bytes`, or an error |

`Version` (1) is the version of the saved format; reading rejects other versions, unknown backends and units, and
operations that do not have exactly the fields of their kind.

`Options` configure `Fuzz`: `Start` (empty selects the default start rule), `Backend` (default `Closure`), `Unit`
(default code points), `Limits` bounding the documents and fresh parses, `Seed`, `Corpus` (the initial texts in the
order the seed selects them; without it, inputs generated from the grammar and the empty text), `Sequences`
(`DefaultSequences` = 100 if zero), `Operations` per sequence, the last of which is a checkpoint
(`DefaultOperations` = 32 if zero), `SaveFailures` (a directory, created if needed; without it a failure's message
includes the sequence as JSON), and `Minimize` with `MaxAttempts`, which saves the original and then the minimized
sequence. The same seed, options and package version generate the same sequences; a saved sequence, not a seed,
is the reproducer.

A `*Failure` holds `Err` (a `*Mismatch`, or an `*InvalidError` for an edit that the document rejected although its
range was on character boundaries), the `Sequence`, its `Path` ("" if unsaved) and, with `Minimize`, the `Minimized`
sequence and `MinimizedPath`. A `*Mismatch` names the `Backend`, `Unit`, the `Event` (the index of the operation, or
-1 for the initial text), the `Text` of the document, the first differing `Path` (such as `value.value[1].end`;
`text` for a wrong text or a rejected undo or redo; `panic.edit`, `panic.document`, `panic.fresh` or `panic.both` for
a panic), and the differing values `Document` and `Fresh` as JSON. `Category` returns `value`, `error`, `text` or
`panic`; `Fingerprint` identifies the kind of failure independently of the input (the category, backend, unit and
first differing location without list indexes). An `*InvalidError` has the `Event` (-1 for the sequence as a whole)
and `Err`; it reports a grammar that does not match the recorded hash or does not compile, an unknown backend or
unit, an edit outside the text or off a character boundary, or an undo or redo without a matching edit. `Failure`,
`Mismatch` and `InvalidError` implement `error`; `Failure` and `InvalidError` have `Unwrap`.
